## 이중화란

> 서비스가 서버나 DB에 의존적이지 않는 상태로 유지하기 위하여 이중으로 구현해놓는 것

## 왜 사용하냐

서비스가 하나의 서버를 이용중이라고 가정하자

그렇게 되었을때 하나의 서버가 멈춰버리면 서비스 전체가 멈춰버리는 상황이 발생함

그래서 서버를 하나 더 두는거임

그렇게 되었을때 다른 서버 하나를 사용하여 서비스가 유지되도록 함

## 이중화의 핵심 목적

### 장애 대비

> 서버 하나 죽어도 다른 서버가 대신 처리함.

```
A 서버 죽음 → B 서버가 처리
```

### 무중단 배포

> 새 버전을 배포할 때 한 서버씩 바꿀 수 있음.

```
A 서버 업데이트 중
B 서버는 계속 서비스 중
```

그래서 사용자는 서비스가 꺼진 걸 못 느낌.

### 트래픽 분산

> 사용자가 많으면 서버 하나가 다 받기 힘드니까 나눠서 처리함.

```
사용자 1 → 서버 A
사용자 2 → 서버 B
사용자 3 → 서버 A
사용자 4 → 서버 B
```
