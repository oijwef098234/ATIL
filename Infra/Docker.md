## Docker란

> 코드 or 서비스, 즉 프로그램 자체를 포장하여 어떤 환경에서든 실행가능하게 하는 도구

## 사용 예시

1. 서비스를 개발함
2. 해당 서비스를 배포하고 싶음, 따라서 코드를 아예 통째로 넘겨줌
    - 여기서 버전, 각종 환경적인 에러 등 여러 문제가 발생함 ← 이 부분 때문에 Docker 사용
3. Docker라는 곳에 올려서 해당 Docker를 실행하여 배포함
4. 문제 없이 동일한 환경을 제공해줌

## Docker의 장점

### 실행 환경 통일

- 내 컴퓨터, 친구 컴퓨터, 서버에서 똑같이 실행 가능.

### 배포가 간편함

- 기존엔 코드 넘겨받고 설정하고 불편했지만
- 아예 실행환경을 구축해놓은 상태라서 그냥 컨테이너를 주고 받으면 됨

---

## 이미지란

> 내 코드, 내 서비스 정보 등등 여러 프로그램에 관한 정보들을 담아둔 프로그램 설계도

- 이미지를 통해 컨테이너라는 것을 생성함

## 왜 필요하냐

- 컨테이너를 만들기 위해서 설계도 역할을 해주는 친구임
- 똑같은 컨테이너를 여러개 만들 때 필요함
- 남들에게 배포할때 컨테이너를 주는게 아니라 이미지를 서버에 올려서 컨테이너를 서버에서 띄워둠

---

## 컨테이너란

> 이미지를 실제로 실행하여 생성된 것

- 이미지에 실행환경이 들어있고, 컨테이너는 그 이미지를 실제로 실행한 상태

예를들어서

백엔드 코드를 이미지로 만들어서 백엔드 컨테이너를 생성하면

내 백엔드 코드는 도커 컨테이너 안에서 실행됨.

---

## Docker Compose란

> 여러 개의 Docker 컨테이너를 한 번에 실행하고 관리하게 해주는 도구

## 사용 예시

- 서비스에 필요한 컨테이너가

Mysql, Spring Boot, Redis 이렇게 세개임

이걸 `docker-compose.yml` 또는 `compose.yml` 파일에 적어둠.

그리고 명령어 하나로 실행함.

```
docker compose up
```

그러면 Docker Compose가 알아서 여러 컨테이너를 켜줌.

|구분|Docker|Docker Compose|
|---|---|---|
|역할|컨테이너 하나하나 실행|여러 컨테이너를 묶어서 실행|
|사용 상황|간단히 하나 실행할 때|서버 + DB + Redis 같이 여러 개 쓸 때|
|설정 방식|명령어로 직접 입력|YAML 파일에 적어둠|
|예시|`docker run mysql`|`docker compose up`|
